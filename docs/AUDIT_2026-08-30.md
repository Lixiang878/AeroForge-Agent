## 结论先行

- 软件链路已完成一轮可验证的可靠性修正；2026-08-31 当前收尾验证为 **160 passed**，`compileall` 通过。
- WSL/OpenFOAM v2412 的偏航稳态小算例真实完成 `blockMesh → surfaceFeatureExtract → snappyHexMesh → checkMesh → simpleFoam`；网格 30,688 单元，最大非正交性 33.581°，最大偏斜 0.605561，`checkMesh` 通过。仅 12 步求解的残差仍高于门限，因此被明确判为未收敛。
- 同尺寸瞬态小算例真实完成 `pimpleFoam`，输出非零时间场和 `forceCoeffs`；这只是字典/运行冒烟验证，不构成物理精度验证。
- 现有 `workspace/diag_case5` 的历史报告写有 Cd=0.449，但当前后处理文件中 `coefficient.dat` 已到 t=640，尾段平均 Cd≈0.485765；旧的 `coefficient_0.dat` 只到 t=550。此前按文件名排序会误读旧文件，现已改为按数据最大时间选择，并把该差异保留为历史产物不一致风险。
- 已引入公开 DrivAerML `run_1/drivaer_1.stl` 作为真实车辆几何：原始文件 753,234 三角面，经过无抽稀的流式 binary 转换和 `z=0.005 m` 地面对齐后，OpenFOAM v2412 `surfaceCheck` 报告单一区域、封闭、每条边连接两个面。来源、CC BY-SA 4.0 许可证、SHA-256 和坐标处理见 [`REAL_VEHICLE_MODEL.md`](REAL_VEHICLE_MODEL.md)。
- 真实模型低成本导入冒烟已完成：55,504 cells，最大非正交性 49.7908°，最大偏斜 1.9273，`checkMesh` 通过；30 m/s、160 步 `simpleFoam` 满足当前收敛门禁，暂定 Cd=0.2338、Cl=0.0548。该结果仅证明导入/网格/求解链可运行，不代表网格无关性或工业精度。

## 尚未宣称完成的 CFD 事项

以下内容需要新的算力或实验依据，不能由本轮代码测试替代：

1. 尚无三套网格的 GCI/网格无关性证据，也没有系统的 y+ 分布审计。
2. Ahmed 结果仍不能宣称达到实验 Cd；`diag_case5` 的历史报告与当前最新后处理文件存在上述时间/数值差异，应重新指定算例、清理旧输出后复算。
3. 尚未使用带支腿的标准 Ahmed STL 隔离几何简化影响；低 Re 大网格稳态震荡的长期瞬态平均仍未完成。
4. 湍流模型、入口湍流、阻塞比、地面处理和尾流区域尚未形成完整单因素/重复算例矩阵。
5. `n_parallel` 目前只生成 `decomposeParDict`，没有自动 `decomposePar/mpirun/reconstructPar` 执行链。
6. `check_symmetry` 没有可验证的场数据输入，现返回 `None`，不能当作“对称性通过”。
7. 外部上传 STL 若未指定 `upload_ground_clearance`，仍要求 z 坐标与地面约定一致；CLI/示例已经支持显式地面对齐，但尚未对未知单位和离地间隙做自动推断。
8. DrivAerML 的 55,504-cell 冒烟与 193,874-cell 尾流展示案例的 Cd 差异很大；这已经暴露网格/壁面处理敏感性，后续必须用统一的三套网格、y+ 和统计窗口重新建立气动系数证据链。

## 真实车辆与软件选择结论

- OpenFOAM 不是当前问题的根因。现阶段主要短板是几何来源、网格分辨率、收敛证据和可视化构图；在同一几何/边界条件下更换求解器不会自动补齐这些证据。
- Fluent 与 STAR-CCM+ 可以作为后续的商业交叉验证/自动网格工具，但应先确认学校或单位的完整学术许可、可用内存和并行额度。Ansys Student 的官方限制是流体物理最多约 100 万 cells/nodes，通常不足以承担详细全车外流场的生产网格；STAR-CCM+ 学生版/学术版也要区分授权上限。
- 建议顺序：先用当前 OpenFOAM + DrivAerML 完成三套网格、y+、时间/统计收敛；若需要 GUI、表面修复和商业支持，再用 Fluent 或 STAR-CCM+ 对同一 STL 和工况做独立复算，而不是立即迁移并把软件更换当作精度证明。
